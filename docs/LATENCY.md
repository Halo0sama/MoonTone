# 校园网 Wi-Fi 与蓝牙输出的延迟优化

更新：2026-10-18。目标是优先保持听感连续，在网络和输出设备允许的范围内降低延迟。没有改动蓝牙编码设置，也没有引入新的用户模式。

## 发现的问题

- 多路原先使用 48 包队列，按常见 5ms 包计算可积压 240ms；包长变化时实际时长也会变化。混音器固定分配约 120ms 的 AudioTrack，默认全部作为有效写入缓冲。
- 单路从 600ms 预缓冲开始；控制器虽然逐步降低目标，但已有队列不会因目标降低而自动消退，因而“目标低”不等于“积压低”。
- 只看欠载次数不足以判断网络变好：现有较大缓冲可能只是暂时挡住了反复出现的校园网尖峰。

## 当前策略

单路与每个混音源共用 `audio/AdaptivePcmBuffer.kt`：

- 默认从 40ms 的 PCM 预缓冲开始，保护目标范围 20–600ms。
- 记录最近 30 秒超出正常包时长的到包间隔；保护目标不低于最近尖峰加 20ms。欠载后还会增加 20ms，并重新预缓冲。反复出现的尖峰不会仅因“暂无欠载”而被忘记。
- 连续稳定至少 5 秒后，每秒最多降低目标 5ms，且仍受近期抖动约束。断连期间不将没有音频视为网络稳定。
- 积压高于目标 20ms 时，稳定后的线性插值时间校正最多约加速 0.5%；队列偏低时最多约减速 0.5%，逐步恢复余量。不通过整包跳播降低正常积压。该做法有极小的速率/音高变化，尚需真实音乐听感验证。
- 队列以实际采样帧数约束内存，硬上限 640ms；极端超过上限时丢弃最旧内容并对接缝作短渐变。它是异常积压保护，不是正常的延迟追赶策略。

输出由 `audio/PlaybackBufferTuner.kt` 管理：预留约 120ms 或设备要求的容量，有效写入上限从 30ms 开始。遇到 AudioTrack 欠载时增加余量，连续稳定后缓慢尝试回到 20ms。系统可能按设备约束调整请求值。蓝牙、USB 或其他路由切换后以实际返回值为准。

多路请求 Android 低延迟输出，并提升 PCM 接收线程优先级。单路写入线程绑定单次 AudioTrack 和缓冲，处理短写，停止时先唤醒阻塞写入再回收，避免复用后写错轨道。

Android API 依据：[AudioTrack 有效缓冲与欠载计数](https://developer.android.com/reference/android/media/AudioTrack#setBufferSizeInFrames(int))、[低延迟输出配置](https://developer.android.com/reference/android/media/AudioTrack.Builder#setPerformanceMode(int))。

## 验证方法与边界

运行 JVM 测试可重放稳定输入、不同包长、突发恢复和周期尖峰；Android 测试使用真实 AudioTrack，验证小于旧预缓冲量的输入能够开始播放、混音线程能够消费 PCM、反复启停能够释放线程。完整报告仍保存在 `echolink-app/app/build/reports/`。

测试里的 20ms、30ms、40ms 等数值是软件配置或队列深度，**不是 PC 发声到蓝牙耳机出声的端到端测量**。模拟器不能证明校园网和当前耳机的听感。首次尚未观察到的长停顿、真正丢包或超过保护范围的断流，仍可能导致欠载；“零卡顿”是优化优先级，不是当前可保证的结果。

## 本轮验证记录

- JVM：31 项通过，含 8 项新增自适应缓冲测试，覆盖原生复用数组、时长上限、不同包长、欠载保护、立体声、时间校正及周期尖峰。
- Android：12 项通过，含 3 项新增真实 AudioTrack/混音测试；模拟器实测 120ms 分配容量对应的有效写入缓冲为 30ms，100ms 的输入足以让单路开始播放，反复启停能够回收线程。
- 合成周期抖动：每 2 秒发生一次 100ms 到包停顿，学习阶段后继续模拟至 50 秒；保护目标维持 120ms，最终队列约 125ms，后续欠载 0 次、整包丢弃 0 次。
- 合成网络恢复：两次 100ms 停顿后恢复稳定输入，队列从约 115ms 最终回落到约 35ms，目标恢复 20ms；首次未知停顿仍出现 1 次欠载，未通过修改统计掩盖。此项模拟至 100 秒，正常追赶过程中整包丢弃 0 次。
- 实际手机只读诊断：活动蓝牙连接为 LHDC V3 / 48kHz / 24bit，A2DP 输出线程报告约 162ms 延迟。现有已安装版本连续三次调试状态均为 `CONNECTED`、目标 40ms、待播约 510ms、丢帧与欠载 0；这印证了目标下降而旧积压不消退的问题。这些调试统计并非完整声学测量，也没有将新版安装到手机上进行前后对比。

Debug 与未签名 Release 构建通过；Lint 为 0 errors、29 warnings。日志：`echolink-app/app/build/reports/latency-final-verification.log`，只读手机基线记录：`echolink-app/app/build/reports/latency-phone-baseline.json`。手机诊断所用临时 ADB 转发已经移除；没有改变手机蓝牙设置或中断其串流。
